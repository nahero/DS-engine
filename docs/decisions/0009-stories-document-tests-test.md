# 0009 — Stories document, tests test

**Status:** accepted · 2026-10-01 · supersedes the "play functions are the flow tests" part of [0008](0008-stories-are-tests.md)

## Context
After 0008, Storybook held about 400 stories: screen stories and multi-step flow plays (bulk approve, inline correction, senior approval…). It had become a test harness, which made the catalogue harder to read and put tests where a component library's docs belong.

## Decision
- Storybook is the catalogue, organised by folder:
  - **Foundations**;
  - **UI** (`components/ui`);
  - **Patterns** (`components/patterns`, the design-system composites mirrored in Figma);
  - **Layout** (`components/layout`);
  - **Claims** (`features/claims`, kept because later screens will reuse them).
- Stories show states, not flows. Screens have no stories.
- Behaviour lives in tests:
  - `*.browser.test.tsx` next to feature components and screens (Vitest browser mode, axe, light + dark/compact);
  - Playwright `e2e/` for cross-screen journeys, routing, keyboard paths, axe per screen and viewport, and visual regression (Linux baselines from CI).
- Stories still run as tests (axe in two modes), so the catalogue can't regress either.
- Gates: `check:stories` (every component has stories) and `check:tests` (every feature component and screen has tests).
- Patterns never import from `features` or runtime values from `data`.

## Consequences
- Two places to look (stories for how it looks, tests for how it behaves), each with one job.
- Visual baselines are Linux-only, regenerated by a manual workflow.
